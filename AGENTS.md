# Інструкції для агентів — AIRSPEED

## Призначення та джерела істини

Автономний стендовий індикатор повітряної швидкості: ESP32 CYD з вбудованим
екраном та Matek ASPD-4525. Робочий сценарій власника — пропелер у каналі,
очікувана швидкість 30–80 м/с. Спілкуйтеся з власником українською.

Перед змінами прочитайте `README.md`, `docs/PROJECT_STATE.md`,
`platformio.ini` та відповідні частини `src/main.cpp`.
Фактичний код і конфігурація важливіші за старі пропозиції в переписці.
Це PlatformIO / Arduino C++, а не проєкт LVGL, попри назву товару.

## Структура

- `src/main.cpp`: читання датчика, калібрування, NVS, UI та serial.
- `platformio.ini`: середовище `cyd`, піни, драйвер і версії платформи.
- `lib/TFT_eSPI-2.5.33/`: повна стороння бібліотека з ліцензією. Не змінюйте
  її для звичайних змін застосунку; налаштування задаються build_flags.
- `tools/serial_check.py`: обмежене читання COM-порту; відкриття може
  перезапустити ESP32 через DTR/RTS. Не надсилає команд калібрування.
- `tools/package.ps1`: пакування вихідного проєкту та перевірка ZIP.
- `docs/PROJECT_STATE.md`: стан, обмеження й ручні перевірки.
- `.pio/`: генеровані файли, не редагувати й не пакувати.
- `backups/`: приватна копія flash, якщо є; не включати в архів вихідного коду.
- `dist/`: створені архіви, не включати рекурсивно в нові архіви.

## Перевірене обладнання — зберегти налаштування

ESP32-D0WD-V3, 4 МБ flash, CH340, історично COM10. Перед новою прошивкою
перевіряйте порт: він не гарантовано залишиться COM10 на іншому ПК.

| Пристрій / сигнал | Налаштування |
| --- | --- |
| Matek SDA / SCL | GPIO27 / GPIO22, CN1, I2C 100 кГц |
| Matek адреса | 0x28 |
| Matek живлення | 5 В; GND спільний; логіка I2C 3,3 В |
| Екран | **ST7789**, TFT_eSPI 2.5.33 |
| Екран SPI | HSPI: SCLK14, MOSI13, MISO12, CS15, DC2 |
| Підсвічування / reset | GPIO21 HIGH / TFT_RST=-1 |
| Формат | 240×320 фізично, rotation=1 → 320×240 альбомно |
| Колір | BGR, TFT_INVERSION_OFF |
| SPI write / read | 10 МГц / 1 МГц |
| BOOT | GPIO0, INPUT_PULLUP, коротке натискання після запуску: ZERO |

Не переводьте екран назад на ILI9341 за назвою плати: це вже спричиняло
смуги, неправильну орієнтацію й обрізання. Ідентифікація на реальній платі:
raw DB=`85 FF ...`, DC=`52 00 ...`; користувач підтвердив правильне
зображення після переходу на ST7789. Не використовуйте GPIO22 для RGB LED:
він зайнятий SCL. Touch CS33 та SD CS5 зараз лише утримуються HIGH.

## Поведінка вимірювань

- MS4525DO type A, ±1 PSI: декодування 14-бітного тиску 10–90% шкали,
  1 PSI = 6894,757 Па; знак за прийнятим підключенням трубок.
- Температура сенсора — не гарантовано температура повітря.
- Фільтр тиску: EMA з коефіцієнтом 0,12; спочатку фільтрується тиск,
  потім береться квадратний корінь. Не називайте це середньою швидкістю за секунду.
- IAS = sqrt(2*abs(ΔP)/1,225), від'ємний тиск менше -10 Па позначається REVERSE.
- Зона нечутливості швидкості: abs(ΔP) ≤ 3 Па → 0,0 м/с. Сам тиск
  не обнуляється. Це приховує також реальні швидкості до ~2,21 м/с;
  вище порога формула незмінна. Не видавайте це за підвищення точності.
- Нуль тільки вручну: BOOT або serial `z`/`Z` при зупиненому потоці.
  150 свіжих вибірок; відхилення при розмаху >40 Па або abs(offset)>500 Па;
  тайм-аут 10 с. При невдачі зберігається попередній нуль.
- Preferences namespace `airspeed`: `zero` (float Па), `cal` (bool).
  Не стирайте NVS без потреби. Не калібруйте автоматично при запуску.
- Швидкість прихована без калібрування, під час ZERO або за відсутності
  свіжих даних понад 500 мс. Статус байтів датчика перевіряється в коді.

## UI: регресії, які не можна повертати

Темний екран, велике значення км/год; три картки м/с, Па, °C.
Малювання через sprite (16-bit, fallback 8-bit, потім пряме малювання).
Верхній статус має фіксовану ліву позицію x=258, y=10; область
x=240..319, y=4..23 очищається. Нижній рядок y=216..239 очищається;
ZERO стоїть у x=232, деталі — x=268, y=225. Не повертайте вирівнювання,
через яке слова зміщувалися при зміні довжини й залишали фрагменти літер.
При переходах станів код також очищає відповідну область фізичного LCD.

Зберігайте ці координати, якщо користувач не просить інше. Зміни візуального
вигляду перевіряйте на фото/самій платі: успішна збірка та serial не
підтверджують правильне зображення. Не заявляйте про візуальну перевірку,
якої не було.

## Робочий процес

1. Робіть зміни вузько за запитом, не переробляйте вимірювання через правку UI.
2. Зберіть `pio run -e cyd`. На попередньому Windows-ПК executable:
   `$env:USERPROFILE\.platformio\penv\Scripts\platformio.exe`.
   Не вимагайте цього абсолютного шляху на іншій машині.
3. Залежності: espressif32 6.9.0 / Arduino 2.0.17 та vendored TFT_eSPI 2.5.33.
   Новому ПК потрібен PlatformIO Core і початкове завантаження toolchain/framework.
4. Прошивайте `pio run -e cyd -t upload` лише коли це входить у поточне
   доручення. Закрийте serial monitor перед записом. Запит на документацію
   або архів сам по собі не потребує прошивання контролера.
5. Перевіряйте compile/upload exit code; за потреби читайте bounded serial log.
   Після змін UI виконайте перевірки з `docs/PROJECT_STATE.md`.
6. Не запускайте ZERO віддалено без підтвердженого зупиненого потоку.
7. Для пакування: `powershell -NoProfile -File tools/package.ps1`.
   Архів містить джерела, docs і бібліотеку, але не `.pio`, приватний flash,
   встановлений Python/PlatformIO або сторонні облікові дані.

Не додавайте SD, touch, Wi-Fi, автокалібрування чи LVGL лише тому, що вони
були запропоновані в старому чаті. Це можливі майбутні функції, не поточні.
Документуйте залишкові обмеження чесно; прилад ще не метрологічний еталон.
